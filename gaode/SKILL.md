# 周边去哪儿：基于高德的地点推荐助手

## 一、名称、用途与适用场景

用户用一句话说出"我在哪、想找什么"，本 Skill 指导你查询高德地图的真实地点与步行路线，返回少量可信、可核实的推荐。完成一次"提出需求 → 查询高德 → 返回推荐"即可，无需多轮交互、长期记忆或跨城市经验。

适用场景：单轮输入包含城市、起点（评测时提供明确起点坐标，不需要设备定位）以及自然语言需求，需求中可能出现地点类型、步行时间上限、推荐数量、排序偏好等要素。

## 二、需求解析（动手前先明确条件）

从用户输入中提取以下要素；缺失时按缺省值执行，并在回答开头用一句话说明所采用的默认条件：

| 要素 | 示例 | 缺省值 |
| --- | --- | --- |
| 地点类型/关键词 | 咖啡馆、餐厅、公园 | 无有效类型时按"结果不足"处理（见第五节） |
| 推荐数量上限 | 最多 3 家 | 3 |
| 步行时间上限 | 步行不超过 15 分钟 | 不设硬上限，但仍必须给出真实步行时间 |
| 排序偏好 | 优先近一点的 | 按步行时间从短到长排序 |

- 这是单轮任务：**不要向用户追问**，按缺省值直接执行。
- 起点坐标为高德 GCJ-02 坐标，格式 "经度,纬度"，直接使用，不要做坐标系转换。若用户只给地名没给坐标，先调用地理编码（maps_geo，参数 address、city）转成坐标。
- 不要调用 IP 定位；不要虚构起点。

## 三、工具调用流程

环境会配置好高德 MCP Server 的工具。下文使用常见工具名（maps_around_search、maps_direction_walking 等），**以运行环境实际暴露的工具名为准**，名称可能略有差异（如步行路径规划也叫 maps_direction_walking_location）。本题核心只依赖两项能力：地点搜索、步行路线规划；地理编码、距离测量仅作辅助。

### 第 1 步（可选）确认起点

- 有坐标就直接用。可调用逆地理编码（maps_regeocode，参数 location）获取起点所在省市区，仅用于回答中的位置描述；调用失败就省略这一句，不要编造。

### 第 2 步 地点搜索

- 调用周边搜索（maps_around_search）：keywords=用户要的地点类型；location=起点坐标；radius=搜索半径（米）。
- 半径估算：步行 1 分钟约 80 米。用户给了步行时间上限 T 分钟时，radius = T × 80（可再加两成余量，上限 5000）；没给上限时 radius 取 1500 左右。
- 一次搜索尽量多拿候选（通常返回约 10 条），宁多勿少，后续靠路线数据筛选。候选太少时：半径放大一档（如 1500 → 3000）再查一次；工具支持翻页时也可翻页。
- 若周边搜索不可用，退化为关键词搜索（maps_text_search，参数 keywords、city），跳过直线距离预筛，直接对返回地点逐一查步行路线。

### 第 3 步 步行路线规划（逐家查询）

- 对每个候选地点调用步行路径规划（maps_direction_walking）：origin=起点坐标，destination=该候选的 location 坐标。
- 从返回的 paths 中取 distance（米）和 duration（秒）。各地点都是"起点 → 该地点"的独立路线，互不串联。
- 单次调用失败可重试 1 次；仍失败就放弃该候选，**不得用估算值顶替**。步行路线规划限 100 公里内，本题场景不会超出。

### 第 4 步 筛选（硬性条件，逐条用数据核对）

1. **步行时间达标**：分钟数 = duration ÷ 60 后向上取整；分钟数大于用户时间上限的候选，一律不得进入推荐列表。
2. **类型相符**：候选的名称或类型字段要与用户需求一致（如"咖啡馆"对应咖啡厅类目；名称含糊时看类型字段，拿不准就不要列入）。
3. **去重**：同一 POI 或同址分店只保留步行更近的一家。
4. **数据完整**：缺 location、查不到路线的候选不进入推荐。

### 第 5 步 排序与数量

- 默认按步行时间从短到长排序；用户明确的其他偏好只有在返回数据支持时才优先（例如"评分高"需要详情数据里有评分，没有就仍按步行时间排）。
- 取排序后的前 N 家（N 为用户指定数量，缺省 3）。不足 N 家时给出实际数量并说明原因。
- 用户说"优先近一点"时，推荐顺序必须与路线查询结果一致（近的在前），推荐理由里也应体现相对远近。

## 四、回答格式

先一句话交代起点与检索条件，再用表格列出推荐，最后按需补充说明。推荐理由必须出自返回数据（类型、位置、相对距离），一句话即可。

示例（数据为示意，实际以工具返回为准）：

> 起点：杭州市西湖区（坐标 120.xxx,30.xxx）。已按"步行 ≤ 15 分钟、优先近"筛选，共推荐 2 家（另 1 家候选步行约 22 分钟，超出时限未列入）。

| # | 地点名称 | 地址 | 步行距离 | 步行时间 | 推荐理由 |
| --- | --- | --- | --- | --- | --- |
| 1 | XX咖啡（XX路店） | 文三路 XX 号 | 约 680 米 | 约 9 分钟 | 三家中步行最近，紧邻起点所在街区 |
| 2 | XX咖啡（XX广场店） | XX 广场 1 层 | 约 1.1 公里 | 约 14 分钟 | 位于商场内，顺路可逛（营业情况未核实） |

- 名称、地址、距离、时间一律取自工具返回数据：名称、地址照抄；距离就近取整（不足 1 公里用"约 XXX 米"，超过用"约 X.X 公里"）；时间用"约 X 分钟"。
- 不输出工具调用的流水账和中间 JSON；回答保持简洁，能帮用户直接做选择。
- 不编造"环境安静""排队少""评分高"等无数据依据的描述；确有必要提及时标注"（未核实）"。

## 五、异常与边界处理

| 情形 | 处理方式 |
| --- | --- |
| 工具调用失败或超时 | 重试 1 次；仍失败则如实说明"高德服务暂时不可用，无法给出经核实的推荐"，建议稍后再试；步行路线规划持续失败时，可用距离测量（maps_distance）的步行距离/耗时作为降级数据源，并在回答中注明 |
| 搜索无结果 | 换更通用的关键词（"咖啡馆"→"咖啡"）或扩大半径重查一次；仍无结果则如实说明，并建议用户放宽时间、距离或关键词 |
| 合格候选不足 N 家 | 推荐实际数量，说明淘汰原因（如其余候选超出步行时间上限） |
| 超时但有结果的边界 | 超出时间上限的地点不进入推荐列表；如对用户有价值，可在表格外用一句话带过并注明超出时限 |
| 起点无效或与城市不匹配 | 如实说明无法执行本次推荐，不要硬查、不要换起点 |
| 营业状态、排队、安静程度等无数据 | 不编造；需要提及时标注"未核实" |

**红线（硬性要求）**：不编造地点、地址、距离或时间；不用直线距离替代步行时间；超出步行时间上限的地点不列为符合条件的推荐；不在文件或回答中出现任何 API 密钥（密钥由评测平台配置）。
